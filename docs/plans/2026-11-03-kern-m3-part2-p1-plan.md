# kern M3 part 2, project 1 implementation plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking. Implementers and reviewers run on Opus. Lanes below run at the same time, each in its own worktree.

**Goal:** Close the 33 items part 1's paid check left open, self-review's skipped proofs and the audit's M3 adopt rows, and let a go commit a project's own hook files, with no gate falling.

**Architecture:** G16 judges a project's hook files by where they resolve, not by their names. One script, `review-check`, runs self-review's deterministic pass and prints the verdict floor, so a `fix first` round cannot skip its proofs. Run rules gain the bug and tests-only routes and U1 on first builds; graders and fixtures catch what the paid check could not see.

**Tech Stack:** bash 3.2 and awk hooks, Node 22 tests and evals, bats.

**Spec:** `docs/specs/2026-11-03-kern-m3-part2-p1-design.md`, under `docs/specs/2026-11-03-kern-m3-part2-overview.md`. Items: `docs/research/2026-10-31-m3-item-sort.md`, section "Part 2, from part 1's paid check". Adopt rows: `docs/research/opus-audit-2026-10-22.md:476-497`.

## Decisions made in this plan

| Decision | Why |
|---|---|
| G16's write class: Write, Edit, NotebookEdit, `cp`, `mv`, `install`, `tee`, `sed -i`, a `>` or `>>` target, `git add`, `git mv`. Any other verb keeps today's vote | The design names write, edit, copy, move and `git add` |
| A read in a project's hook folder takes the same `KERN_ROOT/hooks` test as a write | A read is never riskier than a write, and today a read in a kern worktree's `hooks` folder asks |
| The verdict script is `scripts/review-check WT PACKAGE (--spec SPEC \| --no-spec) [--test FILE] [--autopilot]` | Neither spec flag is a usage error, so a round cannot drop the spec by leaving a flag out; `--autopilot` turns an unresolved `verify.fast` into the named skip, as self-review's autopilot section already rules |
| The bug and tests-only routes' spec is `<kern-dir tmp>/ticket-<id>.md`, `<id>` as the `kern mode:` line shows it | One file per go; self-review step 4 already sends tracker text under `kern-dir tmp` |
| The six go setups write `export const sum = (a, b) => Number(a) + Number(b);` | Strings then sum as numbers before and after the rounding, so the ticket changes no behaviour it does not name |
| The `tax` test adds `assert.strictEqual(tax(10.5), 2.1)` | `10.5 * 0.2 === 2.1` in Node 22, so the base passes; `Math.round(net * 0.2)` gives 2 and `toFixed(2)` a string |
| The size ask gets no mechanism in project 1 | Only a Stop hook reads a reply, and `hooks/hooks.json` has no Stop entry. Project 2 builds that hook (G7); until then `workflow-execute-plan-size-breach` is a known limit, graded on the reply alone |
| `ScheduleWakeup` is denied through `--disallowedTools` in `PERMISSIONS` (`scripts/lib/claude-run.mjs:9`) | Every runner builds its argv there |
| Audit row L497 (behave `CHECKS` known rows) lands in Task 12 | Task 12 adds `CHECKS` rows to the same files |
| The design's adopt count is corrected in this plan's commit | The four deferred clauses sit in three rows (L482, L488, L489), so 19 rows land or are recorded closed, and L482's back-edge clause is already at HEAD |
