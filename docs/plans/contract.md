## Hook input and output facts (Claude Code 2.1.296 docs)

- stdin is one JSON object. Common fields: `session_id`, `cwd`, `hook_event_name`, `permission_mode`, `transcript_path`; subagent context adds `agent_id`, `agent_type` (plugin agents are `kern:<name>`).
- SessionStart: `source` in `startup|resume|clear|compact|fork`. Plain stdout is added to context. Cap 10,000 chars per string.
- UserPromptSubmit: `prompt`. Plain stdout is added to context. Also fires for scheduled tasks, background subagent reports and cross-session messages.
- UserPromptExpansion: `expansion_type` (`slash_command`), `command_name`, `command_args`, `command_source`, `prompt`. Plain stdout is added to context.
- SubagentStart: must print JSON `{"hookSpecificOutput":{"hookEventName":"SubagentStart","additionalContext":"..."}}`.
- PreToolUse: print `{"hookSpecificOutput":{"hookEventName":"PreToolUse","permissionDecision":"allow|ask|deny","permissionDecisionReason":"..."}}`, exit 0. Claude Code applies deny > defer > ask > allow across hooks. Printing nothing means no opinion (normal permission flow).
- Exec form: `"command": "bash", "args": ["${CLAUDE_PLUGIN_ROOT}/hooks/<name>"]`.

## Library API (hooks/lib, sourced by hooks and by scripts/kern-get)

Locale (Task 16m): no file under `hooks/`, and no script a hook names as `scripts/<name>` (today `kern-detect`, which G5 runs, and `kern-get`, which a rendered line names), makes a locale change bash must undo. A command pinned to the C locale runs as `env LC_ALL=C cmd`; no function sets `local LC_*` or `local LANG`, and a character class in a bash pattern lists its characters instead of a range (`[!ABC...xyz0123456789_-]`). Homebrew bash 5.3.15, which a hook's `bash` resolves to on macOS, segfaults now and then when a subshell undoes such a change, and only while neither `LANG` nor `LC_ALL` is set (Task 16l). Each entry hook (`session-start`, `prompt-submit`, `pre-tool-use`, `subagent-start`) runs `[ -n "${LANG-}${LC_ALL-}" ] || export LANG=C` as its first command: an unset `LANG` already means the C locale and an `LC_*` still overrides it, so no output changes, and the trigger is gone for every command the hook runs. Lint rule 17 checks both forms; `tests/hooks/locale.bats` runs the former crash sites, the entry guard and a G20 `.md` Write and Edit in 300 fresh bash 5.3 processes each with no locale.

`json.sh` (POSIX awk; no jq dependency, jq unused even when present so behaviour is identical everywhere):
- `json_get KEY` reads JSON from `$KERN_INPUT`; prints the decoded string value of the first `"KEY":` whose value is a string; handles `\" \\ \/ \n \t \r \b \f`; leaves `\uXXXX` as the literal six characters. Exit 0 found, 1 absent, or 1 when the first `"KEY":` holds a value that is not a string (it does not search further).
- `json_get_raw KEY` prints the raw JSON text of the first `"KEY":` value (object, array, string or literal). Exit 0 found, 1 absent.
- `json_escape` reads stdin, prints it escaped for a JSON string body (no surrounding quotes): `\` and `"`, tab, CR and LF as short escapes, every other byte below 0x20 as `\u00XX`. The output is always a valid JSON string body, whatever bytes a reason echoes.
- `json_ok` exit 0 when `$KERN_INPUT` starts with `{` and ends with `}` after trimming whitespace, else 1.

`settings.sh`:
- `kern_main_root [dir]` prints the main worktree root (`dir` defaults to the hook's `cwd`). This is the first `worktree ` path of `git -C <dir> worktree list --porcelain` when that path holds a `.git` entry or is a bare repository. Otherwise, in a submodule or a `--separate-git-dir` checkout, it is the git dir's `core.worktree` resolved against the git dir, or else `git rev-parse --show-toplevel` of a checkout that is not a linked worktree. Exit 2 when dir is not a git repo, when it is a linked worktree of a separate git dir, or when the checkout cannot be found.
- `settings_get KEY [DEFAULT]` prints the value; `settings_source KEY` reports where it came from. For `protected_targets`, `never_commit`, `branch.protected` and `deploy.envs` the value is the union of every layer, highest first, joined with `, `; items are trimmed and a repeated item is dropped, keeping the first; the default applies only when no layer sets the key, an empty value in a higher layer clears nothing, and `settings_source` lists every file that sets it. Order: `$MAIN/.claude/kern.local.yml`, `$MAIN/.claude/kern.yml`, `$HOME/.claude/kern.yml`. Exit 0 found or defaulted, 3 unset with no default. Exit 4 (Task 16l, fix rounds 1 and 2) when a layer that could set KEY could not be read, or the list of layers could not be made. The layers that read still count, the user's file among them: a policy key then prints `deny` when one of them says deny, else `unknown`; `rebase.push` prints `ask`; any other key, `kern` included, prints what the readable layers and DEFAULT give, so the user's `kern: off` holds and a caller that guards on the key fails closed on 4. `settings_unread_why KEY` prints the cause for a reason: "git cannot open this repository, so kern cannot read its .claude settings (run `git status` to see why)" for `_settings_files` exit 2, "<file> could not be read", "git cannot tell whether <file> is your own untracked file (run `git status` to see why)" for a `kern.local.yml` whose loosening value git cannot vouch for, "<file> is owned by another user, so kern does not take it as your own file" for one another user owns (Task 16m), or "a kern settings file could not be read (retry)". A layer is read by `_settings_read FILE KEY` (sets `_KERN_SV`; exit 0 found, 1 not set, 2 unread, after one retry): its command substitution ends with a status line, so one whose pipe cannot be made (status 0, no output) reads as unread, not as unset.
- `_settings_files`: when git finds no main worktree root, `_settings_walk_root DIR` finds it from the `.git` at or above the directory without running git (Task 16l, fix round 2): a `.git` directory holding a `HEAD` gives its parent; a `.git` file gives its `gitdir:`, whose `commondir` leads to the main repository (or to a bare one), or, with no `commondir` (a submodule), the directory holding the file. So a repository git refuses (dubious ownership, git unable to run, a removed linked worktree's directory) still reads its project layers. `_settings_files` exits 2 only when that `.git` is broken (a `.git` directory with no `HEAD`, a gitdir that is gone, anything else named `.git`): the project layers are unknown, and `settings_get` and `autopilot_denied_by` count them as unread. Outside any repository it exits 0 as before.
- `settings_unknown_keys` prints `file<TAB>key` for every key not listed in `kernel/settings.md`'s key table.
- File format: one `key: value` per line; `#` starts a comment at line start or after whitespace outside quotes; surrounding single or double quotes stripped; lists comma-separated; leading and trailing whitespace trimmed; later duplicate keys in the same file win.
- `policy_for ACTION` where ACTION is `commit|push|pr|tracker|review.post` prints `ask|auto|deny` from `<action>.policy` (`review.post_policy` for review.post). `pr.policy` value `draft-after-approval` is read as `ask`. Unknown value prints `ask`. A policy that could not be resolved prints `unknown` (`deny` when a readable layer says deny), from settings_get's exit 4 or its own substitution coming back without its status line. G1, G2, G3, G5 and G14 ask on `unknown` with "<key> unknown: <cause>", and on an empty `policy_for` result, their own substitution failing, with "<key> could not be read (retry ...)"; under autopilot such an ask is a deny.
- `kern_enabled` exit 0 unless the resolved `kern` key is `off`.

`state.sh` (session state):
- State dir: `${CLAUDE_PLUGIN_DATA:-$HOME/.claude/plugins/data/kern-kern}/sessions`. File `<session_id>.state`, mode 0600, flat `key: value` lines: `voice`, `surface`, `autopilot` (`on|off`), `since` (ISO 8601 UTC).
- `state_file SID` prints the path; refuses a session id that is not `[A-Za-z0-9_-]+` (exit 2).
- `state_get SID KEY` prints the value, exit 1 when unset, 2 for a bad session id or a symlinked state file.
- `state_set SID KEY=VALUE...` atomic: writes a temp file in the same dir with umask 077, then `mv`; refuses when the target is a symlink (exit 2). awk copies the old lines, but those of the keys set, straight into the temp file, and the keys set follow, a key given twice taking its last value. A read of the existing file that fails is tried once more; when it fails again nothing is written (exit 2), so no key is lost. A failed `mv` exits 2 and removes the temp file (Task 16l). A write of `autopilot=off` never depends on a read: when `state_set` exits non-zero, prompt-submit (`/kern:autopilot off`, "stop autopilot", "autopilot off") calls `state_reset`, which reads nothing, and says that voice and surface went back to their defaults (Task 16l, fix round 1).
- `state.sh` and `settings.sh` make no locale change bash must undo (see Locale above): awk runs as `env LC_ALL=C awk`, and ids and keys are checked against listed letters. Homebrew bash 5.3.15 on macOS (measured 2026-10-21) segfaults about once in 16 runs when a subshell undoes such a change, and only while neither `LANG` nor `LC_ALL` is set (`LC_CTYPE` alone does not prevent it), and the old `state_file`'s `local LC_ALL=C`, run inside `$(state_file)`, is what made `state_get` fail and prompt-submit reset the state (Task 16l, fix round 2).
- No state function takes the state path or reads the state through a command substitution: one whose pipe cannot be made (a full fd table) gives status 0 and no output, which would read as no file or an empty state (Task 16l, fix round 1).
- `state_reset SID` writes defaults from settings: `voice` from `default_voice`, `surface` from `mode.surface` (default `auto`), `autopilot: off`, and `since`.
- `state_ensure SID` (M2b, Task 16l) runs `state_reset` only when the session has no state file. A state file that exists is never reset: a read of it that fails is tried once more, and when that fails too the file is left as it is and each reader fails safe for its own call (`autopilot_on` reads off). Exit 0 when the state reads or was written, 1 when an existing file did not read, 2 for a bad session id, a symlinked state file or state dir (left alone), or a failed write. prompt-submit calls it on every prompt and command expansion, and session-start on `compact` and `resume`; `startup` and `clear` call `state_reset`.
- `default_voice` (M2b) prints `normal` or `terse`: `mode.voice.headless` (default `normal`) when `CLAUDE_CODE_ENTRYPOINT` starts with `sdk-` (a `claude -p` or Agent SDK session), else `mode.voice` (default `normal`). session-start, prompt-submit's `/kern:mode default` and subagent-start with no state use it.
- `autopilot_on SID` exit 0 only when no settings file (local, shared or user) says `autopilot: denied` and `state_get SID autopilot` is `on`.
- `autopilot_denied_by` prints the first settings file, in precedence order, that says `autopilot: denied`; exit 1 when none does. `prompt-submit` and `autopilot_text` name this file in "denied by <file>". It fails closed (Task 16l, fix rounds 1 and 2), each with exit 0 and a text that reads after "autopilot denied by": a layer that exists but could not be read prints `<file>, which could not be read`, a list of layers that could not be made `the settings files, which kern could not list (retry)`, and `_settings_files` exit 2 ``the project's .claude settings, which kern cannot read: git cannot open this repository (run `git status` to see why)``.
- `prompt_hashes` (M2a) reads text on stdin and prints, space-separated, one decimal hash per non-blank line of up to 500 characters (the first 20 such lines), after lowercasing, folding runs of blanks to one space, trimming, and dropping a final run of `.` and `!`. The hash is djb2 mod 2^32, computed in awk under `LC_ALL=C`. State key `prompt_hashes: <hashes>` (M2a) is rewritten by `prompt-submit` on every user prompt that is not wrapped; G20 compares an `approved:` quote's hash with it.

`decide.sh` (PreToolUse votes):
- `vote allow|ask|deny GUARD REASON` records a vote; keeps the strictest (deny > ask > allow); concatenates reasons as `G<n>: <reason>` joined by `; `.
- `emit_decision` prints the PreToolUse JSON for the strictest vote; prints nothing when no guard voted. Under autopilot a final `ask` becomes `deny` with reason suffix `(autopilot: nobody to ask)`.
- `fail_closed REASON` used on parse failure: votes `ask` (becomes `deny` under autopilot).

`gitctx.sh`:
- `git_words CMD` splits a shell command string into simple commands on `;`, `&`, `&&`, `||`, `|`, newlines and unquoted `( )` and `{ }`, and prints one record per line (quotes respected; the bodies of `$( )`, backticks and `-c` scripts, and the arguments of `eval`, are also emitted as records). It returns 0 when it succeeds, so callers may run it under `pipefail`. A newline inside a record, such as a quoted multi-line commit message, is printed as `\037`; decode it before reading lines of a message. Here-doc bodies are data and are left out, except a here-doc read by an sh-family shell with no `-c`, whose body is records. `_shell_words` keeps a quoted newline as `\037` inside its word.
- `git_sub CMDLINE` for a simple command whose head is git (basename, any case): prints `<dir><TAB><subcommand><TAB><rest>` after consuming git's global options (`-C <dir>`, `-c <k=v>`, `--git-dir=`, `--work-tree=`, `--no-pager` and the others the code lists). `dir` defaults to the hook `cwd`.
- `in_main_checkout DIR` exits 0 when `git -C DIR rev-parse --show-toplevel` equals `kern_main_root DIR`. A repository its superproject tracks as a gitlink takes the superproject's answer (`--show-superproject-working-tree`, recursively), unless it shares the superproject's git common dir, as a linked worktree of the same repository does.
- `branch_protected BRANCH` exit 0 when BRANCH is the settings `base_branch`, the origin/HEAD branch, listed in `branch.protected`, or listed in `deploy.envs`; when origin/HEAD is unknown, `main`, `master`, `trunk` and `develop` are protected too. A `base_branch` setting only adds a protected branch. Every branch is protected while one of those three keys reads with exit 4, and so is an empty name: `current_branch` exits 2 when its read of HEAD comes back empty, and G5 reads an empty current branch, its own substitution failing, as "the current branch could not be read" (Task 16l, fix round 2). On exit 4 each guard names the cause (`settings_unread_why`): G6 asks (deny under autopilot) since the staged paths cannot be cleared against `never_commit`; G13 asks on a command that names a client and still checks the targets the readable layers name; G14 asks on a write to an MCP server no readable layer names; G15 votes on every push target (Task 16l, fix rounds 1 and 2). A call that is not a git call is never denied only because a project layer cannot be read, though under autopilot every ask is a deny.
- `current_branch DIR` prints the branch `git -C DIR symbolic-ref -q HEAD` names, without `refs/heads/` (not `rev-parse --abbrev-ref`, which prints `heads/<name>` when a tag shares the name). Exit 1 and no output on a detached HEAD.
- `git_words` (M2a Task 33): with aliases loaded (`KERN_ALIASES` set), the outermost call prints the command's own records exactly as without aliases (content, order and context), then every expansion record after all of them. An inner call splits a record's alias expansion again (`_GW_NOALIAS` set, so its own words are not expanded again) and marks each of its records with a leading tab, which no record of the command starts with; the outermost call moves the marked records to the end and strips the mark. So an expansion never changes the context of a record of the command (a `cd` in it cannot clear G1's or G6's `moved` or G16's `in_sd`), and expansions can only add votes. The alias record itself stays first, so a guard that allows only a command whose first record starts with git or gh never allows an alias. A quoted or escaped head word is never an alias. `_GW_IN` and `_GW_NOALIAS` are unset when `gitctx.sh` is sourced. Without `aliases.sh` loaded, nothing changes.

`aliases.sh` (M2a Task 33; loaded by `hooks/pre-tool-use` before `gitctx.sh`, and `aliases_load` runs for the Bash tool only):
- `alias_snapshot`: prints the shell snapshot to read, or exits 1. `KERN_SHELL_SNAPSHOT` names one (tests); otherwise the newest `snapshot-*.sh` under `${CLAUDE_CONFIG_DIR:-$HOME/.claude}/shell-snapshots`.
- `aliases_load`: sets `_KA_<hex of the name>` (two hex digits per byte) to the expansion of each alias whose expansion holds a word that is git or gh (last path part, any case, quotes removed), and of each alias whose expansion ends in a space (a tab does not count, as in zsh; stored with one space at its end), and `KERN_ALIASES=1` when there is one; it first unsets any `_KA_` variable already set. Nothing from the snapshot is evaluated: awk reads at most its first 4 MB as text. A missing, unreadable or unparseable snapshot sets nothing, and no failure stops the hook. The parsed table is cached in `$(state_dir)/aliases.cache` (mode 0600, written to a `mktemp` file in that dir and renamed over the cache): a first line `kern aliases <_ALIASES_CACHE_V> <length of _ALIASES_AWK><TAB><snapshot path><TAB><size> <mtime> <ctime> <inode>`, then the `<hex><TAB>expansion` lines. A cache whose first line differs, or whose size (stat) is over 4 MB plus its first line, is rebuilt without its lines being read; a symlinked cache file or state dir is never read or written through; a cache that cannot be written is skipped silently.
- `_alias_key FILE`: prints FILE's size, modification time, change time (seconds) and inode (BSD `stat -f '%z %m %c %i'` or GNU `stat -c '%s %Y %Z %i'`); exit 1 when neither reads it. A change time cannot be set back with `touch`; an edit in the same second at the same size and inode is not seen.
- `_alias_table`: reads `<hex><TAB>expansion` lines on stdin into `_KA_<hex>` as data, the way `aliases_load` reads the parse and the cache: a line whose name is not hex digits is skipped, and reading stops after 4 MB.
- `alias_text CMD`: prints the expansion of each record of `git_words CMD` whose head word is such an alias, one per line. `hooks/pre-tool-use` sets `KERN_ALIAS_TEXT` to it for the Bash tool when `KERN_ALIASES` is set, and G2, G3, G4, G13, G14 and G15 match their text prefilter (gh, push, deploy tool and client names) against the command and `KERN_ALIAS_TEXT`.
- `alias_expand SEG`: sets `ALIAS_EXP` to SEG with its head word replaced; exit 1 when that word is not such an alias. The head word is the first word after `NAME=value` words, redirections (with a separate target word) and zsh's reserved words `if then elif else do while until ! { time nocorrect coproc` and `repeat` with its count, as zsh finds it; not after `command`, `builtin`, `exec`, `noglob` or `-`, where zsh does not expand. An assignment word holding a quote, `$` or a backslash hands the search to `_ALIAS_HEAD_AWK`, which splits words at blanks outside quotes, `$( )`, `${ }` and backticks, each `$( )` and `${ }` keeping its own quote state. When the expansion ends in a space, the word right after the alias is replaced too when it is such an alias, as zsh's trailing-space rule does, 8 times; a 9th word that is still such an alias starts a record of its own (after `; `) whose command name is `$KERN_ALIAS_PAST_8`, which G00 reads as built at run time whatever the expansions before it start with (deny under autopilot; no vote interactively, as without aliases).
- `_alias_var WORD VAR`: sets VAR to the name of WORD's `_KA_` variable; exit 1 when WORD is no such alias or holds a byte outside the name characters.
- Parsing: `alias [--] name=value` lines, a CRLF read as LF; value bare, single-quoted with `'\''`, or backslash-escaped. Skipped: `$'...'` and double-quoted values, unclosed quotes, a control byte in the value, names holding a quote, `/`, `$`, a backtick, a backslash or a byte outside printable ASCII, names over 256 bytes, lines over 4096 bytes, and alias lines after the first 1 MB of them. The head-word chain is followed as zsh does: each name at most once, at most 8 times, while the expansion is at most 4096 bytes.
- Shell functions: a `name () {` line in column 0 (zsh's `typeset -f` shape), or a `name () ` line then a `{` line (bash's `declare -f` shape), starts a body that runs to the next `}` in column 0. A function whose body holds a git or gh word (the alias test) gets the expansion `git kern-shell-function`, `gh kern-shell-function` when only gh appears, or both joined by `;`; G1, G5, G6 and G2 read it as an unknown git or gh command, so it asks, and under autopilot is denied. A head word that names such a function ends an alias's chain with that expansion; an alias of the same name wins. Function lines have their own 1 MB bound, so alias lines are read as without functions. The cache format is 2. Not read: a function that runs git only through another function or an alias.
- Accepted limits: the hook input and environment do not name the session's snapshot (measured 2026-10-14: one snapshot per Claude Code process; the Bash tool runs `zsh -c 'source <snapshot> && eval ...'`), so the newest stands in for it. Not followed: aliases inside an expansion other than its head-word chain, global aliases, and an alias defined in the same Bash call and run through `eval`, `$( )` or a backtick (G00 denies an alias definition under autopilot). Over-expansion, harmless because expansions only add votes: G16 runs `git_words` on the lowercased command, so its lookup can find an alias zsh would not run (`gbD` is looked up as `gbd`); and an alias is expanded inside `bash -c`, `sh -c` and ssh remote command text too, where the snapshot's aliases are not defined. An expansion sets no context for the command's own later records: `gaa && git commit -m x` loses G6's stale-index reason, though the decision is unchanged.
