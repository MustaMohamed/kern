# kern 0.2.1 patch

**Goal:** close the fail-open found by the source audit, and three small caveman gaps, as a patch release.

**Base:** `main` at the `v0.2.0` tag. Commits use the `M1:` prefix, named paths only, no attribution trailers.

## P1: PreToolUse fails closed when a library cannot load

Today, with `hooks/lib/settings.sh` or `hooks/lib/decide.sh` missing, `hooks/pre-tool-use` exits 0 with no output, so a `git push --force origin main` gets no kern decision. `kern_enabled || exit 0` exits silently when the function is undefined, and `emit_decision` is undefined when decide.sh is missing.

- In `hooks/pre-tool-use`, source each library with a check. After sourcing, confirm with `declare -F` that every function the dispatcher calls directly exists (at least `json_get`, `json_ok`, `json_get_raw`, `kern_main_root`, `autopilot_on`, `kern_enabled`, `vote`, `fail_closed`, `emit_decision`).
- On any failure, print a literal PreToolUse JSON with `permissionDecision: ask` and the reason `kern G0: hook library <name> did not load; reinstall kern`, then exit 0. Use `deny` instead when the raw stdin contains `"permission_mode":"bypassPermissions"` (allow optional spaces after the colon). Do not depend on any library to build this JSON.
- Spec: extend section 8.4 rule 4 of `docs/specs/2026-10-12-kern-design.md` to "A hook that cannot parse its input, or cannot load its libraries, returns `ask` ...".
- Tests in `tests/hooks/pre-tool-use.bats`: for each of json.sh, settings.sh, state.sh, decide.sh, gitctx.sh, copy the hooks into a temp dir, remove that library, pipe a force-push payload, and assert an ask (or a deny with bypassPermissions). One test that a library which sources but lacks a required function also asks. Session-start, subagent-start and prompt-submit with settings.sh missing: exit 0 and print nothing that is not valid hook output.

## P2: no voice reminder on scheduled prompts

Spec 6.3: headless and scheduled runs skip the reminder. `hooks/prompt-submit` blanks a wrapped prompt, then still prints the mode line and the terse reminder.

- When the trimmed prompt starts with `<scheduled-task`, print no mode line and no terse reminder. The autopilot line still prints when autopilot is on.
- Tests in `tests/hooks/prompt-submit.bats`: a scheduled-task prompt with voice=terse prints nothing; the same with autopilot on prints the autopilot line; `CLAUDE_CODE_ENTRYPOINT=sdk-cli` with voice=terse prints no reminder.

## P3: clean up old session state files

- In `hooks/session-start`, after the state reset, remove from `$(state_dir)` the regular, non-symlink files named `*.state` or `.state.*` whose mtime is older than 30 days, using `find <dir> -maxdepth 1 -type f ( -name '*.state' -o -name '.state.*' ) -mtime +30`. Skip the whole step when the state dir is a symlink. Never remove the current session's file. Errors must not stop session-start or print to stdout.
- Tests in `tests/hooks/session-start.bats`: an old state file is removed; a recent one stays; the current session's old file stays; a symlink named `x.state` stays; a symlinked state dir is left alone.

## P4: more natural-language switches, with a corpus

Switches stay on the first line, so nothing in a longer prompt can flip the mode.

- Add these to `natural()` and `_nl_ok` in `hooks/prompt-submit`:
  - on: `use terse mode`, `use terse`, `enable terse`, `enable terse mode`, `turn on terse`, `turn on terse mode`, `activate terse`, `terse` (whole line), `terse please`;
  - off: `turn off terse`, `disable terse`, `terse mode off`, `exit terse`, `exit terse mode`, `quit terse`, `go back to normal`, `go back to normal mode`, `switch back to normal`, `switch to normal`;
  - a trailing clause on the first line: `<anything>, then go terse` and `<anything>, then stop terse` (also `then` without the comma).
- `terse mode off` must match before `terse mode`. The negation and question guards stay in front of every pattern.
- `be brief` does not switch.
- Create `tests/fixtures/mode-activation/cases.json`: an array of `{ "prompt", "expect": "on" | "off" | "none", "known_failing": bool }`. Cover every phrase above, every existing switch, and at least 15 should-not-switch prompts: negations (`don't go terse`, `do not use terse mode`), questions (`what is terse mode?`, `should I go terse?`), mentions (`the terse mode docs are wrong`, `fix the terse off bug`), quotes (`"go terse" is the phrase`), `be brief`, later-line switches (`fix the bug` then a second line `go terse`), and wrapped prompts. Adapt caveman's `tests/fixtures/mode-activation/cases.json` (under `.upstream/caveman/`) where it fits; caveman is Apache-2.0 and already credited in NOTICE.
- A bats test reads the corpus and runs the real hook for each case, from a voice=normal state for `on` and `none` cases and a voice=terse state for `off` cases. A `known_failing` case that passes fails the test, so the list cannot go stale.
