# kern M3 part 2, project 2 implementation plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking. Implementers and reviewers run on Opus. Lanes below run at the same time, each in its own worktree.

**Goal:** Take a go from its draft PR to `gh pr ready` on green CI, with proof on the running app when a change needs it and a Stop hook that holds the go to that finish line, after landing the four held-back audit clauses and closing project 1's carried items.

**Architecture:** One shell library, `hooks/lib/ci.sh`, reads a PR's checks for both G2 and a new `scripts/ci-wait`, which the run starts in the background so no model turn polls. The run's CI rules live in a new `skills/autopilot/references/ci.md`; the guards read the user's replies through the existing typed-prompt consent, which gains `lease` and `ready`. `hooks/stop` grows a go finish-line check, a report check, the size-ask check and opt-in nudges.

**Tech Stack:** bash 3.2 and BWK awk hooks, Node 22 tests and evals, bats, gh 2.103.

**Spec:** `docs/specs/2026-11-05-kern-m3-part2-p2-design.md`, under `docs/specs/2026-11-03-kern-m3-part2-overview.md`. Carried items: `CHANGELOG.md` Unreleased, Known limits; `docs/research/2026-10-31-m3-item-sort.md`. Audit rows: `docs/research/opus-audit-2026-10-22.md:482,488,489`.

## Review Focus

1. The user answers a class 4 stop with a bare "yes": G1 gives no lease consent, so the lease push is denied, and the run asks again in G1's words. Pinned in Task 2 (consent) and Task 4 (G1).
2. Checks not yet registered when the draft PR opens: `ci-wait` does not report `ci: none` in its first 2 minutes. Pinned in Task 3.
3. A push lands while a `ci-wait` started on the old head still runs: G2 reads the checks at the `gh pr ready` call and the review-check record for HEAD's tree, so the old verdict cannot mark the new head ready. Pinned in Task 4.
4. A session with no go and no `stop.nudge` key: the Stop hook adds no block and exits before its awk scan when the transcript holds no `self-review` and no `size-check`. Pinned in Task 7.
5. After a reported stop, the user asks an unrelated question: the hook's finish-line check stays down for the rest of the go. Pinned in Task 7.

## Decisions made in this plan

| Decision | Why |
|---|---|
| `ci-wait` polls `gh pr checks --json name,bucket` every 30 s inside the script; it does not wrap `gh pr checks --watch` | A loop in a script costs no model turns, needs no `timeout` wrapper (G1 denies wrappers under a go), and `fake_gh` can drive it |
| A check's `bucket`: `pass` and `skipping` pass, `fail` and `cancel` are red, `pending` waits. Red wins over pending | gh 2.103's `--json` buckets |
| `ci: none` only after 2 minutes with no checks, read every 20 s | Checks register a few seconds after a PR opens; a repo with no CI never registers any |
| Consent gains `lease` from `rebase` or `sync` (alone or with ` it`, ` the branch`, ` the pr`, ` the pull request`) and `ready` from `mark it ready` or `mark the pr ready` (with optional ` as` and ` for review`); `leave it` parses with no action | `prompt_consent` splits at `and`, so `rebase and push` gives `lease push` and `leave it and mark the PR ready` gives `ready`; a bare yes stays nothing |
| G2's autopilot draft allow writes `go_phase=pr` in place of `go=`; `_g20_go` refuses approval while `go_phase=pr` | The go lives on through CI; its approval of specs and plans ends at the draft |
| `review-check` writes its output to `<kern-dir tmp>/review-check-<tree>.txt`, `<tree>` the full tree id it reviewed; G2 allows `gh pr ready` only when the file for `git rev-parse HEAD^{tree}` holds `floor: none` | The design's self-review half of ready, checked by the guard at the call. A verdict above the floor rests on the run and the Stop hook's report check |
| A stop's report holds a line that opens `kern stop: ` and names the stop | The Stop hook reads one fixed line |
| CI fix rounds count from `CI round: <N>` lines in the bodies of `git log <base>..HEAD` | A durable count that compaction cannot lose, as self-review's package names are |
| A new `go_live SID DIR` in `hooks/lib/state.sh`, the `live_go` test from `hooks/session-start:115-124` | G2, the Stop hook and session-start then share one reading of a live go |
| plan step 11 saves the review's reply to `<kern-dir reviews>/plan-<slug>.md`; under a go G20 denies writing `status: approved` into a plan until that file holds `Verdict: approve` | The plan review writes no file today (`skills/plan/references/plan-review.md:3`), so nothing could check the order |
| `hooks/stop` joins G16's hook entry files (`hooks/guards/g16-state.sh:45`, `:123`) | It now writes session state, like the other entry files |
| The existing draft go cases now want `gh pr ready` | The exec `gh` stand-in reports no checks by default, and a PR with no CI is marked ready |
| The CI loop's text goes in a new `skills/autopilot/references/ci.md` | `references/run.md` is at its 7,337-byte cap |
| Round 1's expected cost: about $70 to $110 | Part 1's full rounds cost $50 to $56 with 19 exec cases; nine new go cases add up to $54 at their $6 cap |

### Task 3: Read a PR's checks and wait on them

**Files:**
- Create: `hooks/lib/ci.sh`, `scripts/ci-wait`, `tests/scripts/ci-wait.bats`
- Modify: `tests/helpers/common.bash:223-236` (`fake_gh`), `kernel/settings.md`, `docs/specs/2026-10-12-kern-design.md` (5.4 table), `docs/plans/contract.md` (scripts table near `:183-190`, lib list)

**Interfaces:**
- Produces: `ci_read DIR` in `hooks/lib/ci.sh`. Runs `gh pr checks --json name,bucket` in DIR under `with_timeout 10`. Drops checks whose name `ci.advisory` lists (comma-separated, exact, case-sensitive). Prints `check: <name>: <bucket>` per check, then one of `ci: clear`, `ci: red <name>[, <name>...]`, `ci: pending <name>[, ...]`, `ci: none`. Exit 0 for clear or none, 1 red, 3 pending, 2 when gh fails or prints no JSON. An empty array and gh's "no checks reported" both read as none.
- Produces: `scripts/ci-wait WT [--minutes N]`. N: the flag, else `ci.wait_minutes`, else 45; an integer from 1 to 600, else a usage error, exit 2. Reads every 30 s until the read is not pending. `ci: none` stands only after 2 minutes of none. Tests shorten the clock with `KERN_CI_INTERVAL` (seconds between reads), `KERN_CI_SETTLE` (seconds of none) and `KERN_CI_MINUTE` (seconds in a minute); unset, they are 30, 120 and 60. Past N minutes it prints the last read with its last line as `ci: pending <names> (timeout <N>m)` and exits 3. Other exits as `ci_read`.
- Produces: settings rows `ci.wait_minutes` (`45`) and `ci.advisory` (none).
