
### Task 26: Execution evals for commit and finish-branch

**Files:**
- Create: `scripts/lib/claude-run.mjs`, `scripts/lib/exec-grade.mjs`, `scripts/exec-eval.mjs`, `evals/exec/cases.json`, `evals/exec/bin/gh`, `evals/exec/fixtures/app/package.json`, `evals/exec/fixtures/app/src/sum.js`, `evals/exec/fixtures/app/test/sum.test.js`
- Test: `tests/exec-eval.test.mjs`, `tests/hooks/ship-commands.bats`
- Create on a run: `evals/snapshots/exec-<date>.json` (committed)

**Interfaces:**
- Consumes: the commit and finish-branch skills (Tasks 24, 25); guards G1, G2 and G5 (M1); `kern-dir tmp`; `claude -p` with `--input-format stream-json`, `--output-format stream-json`, `--verbose`, `--setting-sources project`, `--strict-mcp-config`, `--no-session-persistence`, `--plugin-dir`.
- Produces:
  - `scripts/lib/claude-run.mjs`: `ISOLATION` (the three isolation flags, four words), `workspace(fixtureDir, { name, origin, branch, setup })` (a project-shaped temp path, `_kern` and `_claude` renamed, a git repo with one commit, an optional bare origin and feature branch, setup commands run there), `runClaude({ cwd, prompts, pluginDirs, model, maxTurns, env, timeoutMs }) -> { argv, events, status, stderr }` (one user turn per prompt, as stream-json on stdin), `toolUses(events)`, `finalText(events)`, `claudeVersion()`. M2b's runners reuse it.
  - `scripts/lib/exec-grade.mjs`: `GRADERS[<case id>]({ events, ghLog, git, branch }) -> { pass, reasons }`.
  - `node scripts/exec-eval.mjs [--case <id>] [--dry-run]`: opt-in, never in CI; model from `KERN_EVAL_MODEL` (default `claude-sonnet-5-5`); a run marks a case INVALID when the transcript shows a `gh` call the stub never logged (the Bash tool did not see the stub first on PATH); writes `evals/snapshots/exec-<date>.json` with the model, `claude --version`, the isolation flags and each case's result and commands; exit 1 unless every case passes.
  - `evals/exec/bin/gh`: logs every call to `$KERN_EXEC_LOG`; answers `pr list` from `$KERN_EXEC_PR` (`none`, `open-at-head`, `open-older`, the latter with `headRefOid` of `HEAD~1`) in JSON, or as bare states for a `--jq` call (the form G2's dedup uses); `pr create` prints `https://example.invalid/pr/8`; it never reaches a network, and the runner also sets `GH_TOKEN=invalid` and `GH_HOST=example.invalid`.
  - Cases: `commit-work-file` (autopilot; `git commit -F` names a file under `.kern/tmp`; no `git add -A`; one commit holding only `src/sum.js`), `finish-menu-first` (no push and no PR before the user picks; the menu is shown), `finish-split-nine-files` (`scope_threshold: 4`; a split proposal; no push, PR or commit), `finish-autopilot-draft` (`gh pr create` carries `--draft` and `--title`; no `gh pr ready`; the branch is on the remote), `finish-pr-at-head` (an open PR at HEAD: no new PR, no push, the PR's URL reported), `finish-pr-older-head` (an open PR at `HEAD~1`: the new commit pushed, no new PR, the URL reported).
  - `tests/hooks/ship-commands.bats`: the exact commands the two skills prescribe, run through the real guards under autopilot from a linked worktree with a gh stub, in CI and with no model.
