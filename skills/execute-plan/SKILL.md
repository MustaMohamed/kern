# execute-plan

Turn an approved plan into verified, reviewed changes, with a record surviving compaction.

Review needs no commits: a task's change is the diff of its worktree's snapshot trees, `tree-before` at dispatch and `tree-after` at return; a verdict holds for that tree only. Subagents get absolute paths (`${CLAUDE_PLUGIN_ROOT}` resolved) and a named model and effort. Only the scripts write `Task N: start`, review, minor and `Task N: complete` lines. An unnamed script exit stops the run: report its output.

## Steps

0. Defer: if the kern settings block names an override for this job, follow that project skill instead, say so in one line, and stop.
1. Gate and ledger: run `bash ${CLAUDE_PLUGIN_ROOT}/scripts/ledger-open <plan>`. It prints the ledger dir (`<ledger>` below is `<ledger dir>/ledger.md`), or exits 2 when the plan has no `status: approved` with the user's quoted words, or when the dir holds another plan's ledger: stop and report it. Never edit the plan's approval. The mode is the typed one, else `execution:`. Line formats and how to append them: `references/ledger-format.md`. If the ledger already held lines past `Main:`, or after compaction, read `references/resume.md` and continue where it says.
2. Steps 2 and 3 run on every invocation, fresh or resumed, and add a `Preflight:`, `Decision:` or `parked:` line only when the ledger lacks that exact line. Run `bash ${CLAUDE_PLUGIN_ROOT}/scripts/plan-check <plan>`; any exit but 0 is a plan defect: stop before any task and report its output. Then `plan-check --graph <plan>`: each `overlap` row becomes a `Preflight:` line with its ruling; this run's `wave` rows feed step 4.
3. Read the plan and spec; one todo per task. A spec or scope conflict the graph does not show: stop and ask; record the answer, or a mechanical call, as a `Decision:` line.
4. In `delegate` mode a `wave` row's tasks may run together, each in its fork, at most `parallel.max`, unless parallel-work step 1 finds an overlap; spawn them in one message as `${CLAUDE_PLUGIN_ROOT}/skills/parallel-work/SKILL.md` step 4 does. Others run serially, in task order. Batch small tasks of one shape (the same one-line edit across files) into one dispatch and one review over their joined Files lists.
5. Once, make the plan worktree: `bash ${CLAUDE_PLUGIN_ROOT}/scripts/wt-new <plan-slug> --plan <plan>` (`<plan-slug>`: the ledger dir's name), adding `--branch <name>` when `branch.pattern` holds `{id}` (the plan's `issue:`). Exit 2: say why and ask. Run the baseline `test.full` there (`kern-get`, else `kern-detect`; both exit 3: ask); a red baseline goes to the user. Then write `Worktree: <path> branch=<name> base-tree=<id>`, the id from `wt-snap`.
6. Per task, in the plan worktree or a wave task's fork from `bash ${CLAUDE_PLUGIN_ROOT}/scripts/wt-fork <plan-wt> <plan-slug>-task-<N>` (exit 2 or 3: say why and ask), run `plan-check --files <plan> <N> > <ledger dir>/briefs/task-N.files`, `bash ${CLAUDE_PLUGIN_ROOT}/scripts/task-brief <plan> <N> <ledger dir>` (`briefs/task-N.md`), `bash ${CLAUDE_PLUGIN_ROOT}/scripts/wt-snap <wt>` (`tree-before`) and `bash ${CLAUDE_PLUGIN_ROOT}/scripts/task-start <ledger> <N> <tree-before>`; exit 2 from any: stop. Write `Wave: tasks <list> forks=<paths>` once a wave's forks exist. Then by mode:
   - `step`: do this task with `${CLAUDE_PLUGIN_ROOT}/skills/implement/SKILL.md`, reporting to `<ledger dir>/reports/task-N.md`; run steps 8 to 10, report, and stop.
   - `inline`: the same for each task, in the plan worktree, with absolute paths and `git -C`.
   - `delegate` (serial or wave): write `<ledger dir>/briefs/task-N.brief.md` from `${CLAUDE_PLUGIN_ROOT}/skills/parallel-work/references/brief-template.md`: SCOPE the `.files` paths, the worktree and `<base-ref>` (the plan branch); CONTEXT `briefs/task-N.md`, the upstream Interfaces and the step 3 rulings; VERIFY `bash ${CLAUDE_PLUGIN_ROOT}/scripts/wt-check <wt> <base-ref>` first, then the task's `Run:`; REPORT `<ledger dir>/reports/task-N.md`, each round opening with its `Status:` line. Run `bash ${CLAUDE_PLUGIN_ROOT}/scripts/brief-check` on it; dispatch only on `brief-check: ok` (else fix each printed line): `kern:implementer` with its model and effort, the brief, worktree, `<base-ref>`, report path and implement SKILL.md path. Pass no `isolation` parameter; kern made the worktree.
7. Status line (none: BLOCKED). DONE goes to review. DONE_WITH_CONCERNS: read the concerns, then review. NEEDS_CONTEXT: answer from the plan or spec, else ask the user, then resume the implementer. BLOCKED: add context or go one model tier up (a `Decision:` line); a task that must be split: stop with a split proposal. Never re-dispatch unchanged.
8. Review: take `tree-after` with `wt-snap`, then run `bash ${CLAUDE_PLUGIN_ROOT}/scripts/wt-diff <wt> <tree-before> <tree-after> --out <ledger dir>/reviews/task-N-<tree7>.diff --allow-file <ledger dir>/briefs/task-N.files`. Its first line is `<package>`, beside `<package>.patch`. Exit 3 (empty): return the task to the implementer. Exit 4 names a file outside the task's Files: pause and ask; on a yes append it to `briefs/task-N.files` with a `Decision:` line, on a no return the task to the implementer. Dispatch `kern:task-reviewer` on `model.reviewer` in mode `task` (`run_in_background: false`) with `briefs/task-N.md`, the report, the package, the worktree and the `review.rules` paths; do not pre-judge findings in the prompt. Save its return as `<ledger dir>/reviews/task-N-r<r>.txt`, r = 1 + the task's review lines. Resolve every "cannot verify" item yourself and rule on each "Declined to judge" line of every review and re-review in a `Decision:` line: settled by spec or plan, the user's call at finish, or a real gap. A real gap is a spec issue; add it to that `.txt` as a finding. Record the verdicts with `bash ${CLAUDE_PLUGIN_ROOT}/scripts/task-review <ledger> <N> <tree-after> <r> <compliant|issues> <approved|needs-fixes>`, adding `--minor "<finding>"` for each Minor finding, which waits for step 12.
9. Fix loop for a spec issue or a Critical or Important finding. Before rounds 2 and 3 write `Task N: fix round=<r> tree=<id>`, the tree just reviewed. Round 2 resumes the implementer with the previous round's `.txt` (SendMessage to its agent id, or `references/resume.md`'s fallback; inline and step: fix it yourself); round 3 dispatches a fresh `kern:implementer` one tier up with a step 6 brief, the report and that file. Each round packages its fix diff with `wt-diff` from the round's tree to a new `tree-after` (`--out <ledger dir>/reviews/task-N-fix<r>-<tree7>.diff`, same `--allow-file` and exits), gets a `re-review` with that file, dispatched, saved and recorded as step 8 does. Still open after round 3, or a re-review finds a bug in an earlier round's fix: stop and escalate with a split proposal; there is no fourth round.
10. Close: `bash ${CLAUDE_PLUGIN_ROOT}/scripts/task-done <ledger> <N> <wt> <tree-after> --probe <package>.patch -- <task test command>`, or `--no-probe "<why>"` in place of `--probe` for a task with no test to probe (docs, config). One command, no shell: a compound `Run:` goes in a `kern-dir tmp` script, passed as `-- bash <path>`. Neither may `cd` or name the worktree's absolute path: task-done runs them there and in the fork. After fix rounds, remake `<package>` from `tree-before`. It writes the complete line only when an approved review saw this tree, the command passes, and the test fails with the change reversed (`probe=ok`) or `--no-probe` gave a reason. A refusal writes nothing and says why. `command exited <n>` or exit 1 (the test passes with the change reversed): return the task to the implementer as the next round (after round 3: the split proposal); `command exited 126` or `127`: stop. Exit 3, an inconclusive probe: rerun with `--no-probe "probe inconclusive: <reason>"` only for a new module or export, or a patch of test files only; else stop and ask. Exit 2: a changed or unapproved tree, review it; a probe error, stop. Under autopilot only, then commit the task's files with `/kern:commit` steps 2 to 6 (a wave task: after step 11).
11. After a wave, each wave task has been closed in its fork through steps 6 to 10. Apply each worker's patch to the plan worktree one at a time with `bash ${CLAUDE_PLUGIN_ROOT}/scripts/wt-apply <package>.patch <plan-wt>`, writing `Applied: Task N patch=<path>` after each `applied`. Exit 3 is a conflict with nothing applied: stop. Then `test.full` there; red: stop.
12. Final review (only the user's word skips it): `ledger-open --summary <ledger dir>` lists the ledger's rulings and minors, then the main checkout's state. Package all with `wt-diff <plan-wt> <base-tree> --out <ledger dir>/reviews/final.diff` (the `Worktree:` line's base tree) and dispatch `kern:task-reviewer` in mode `whole-branch` on `model.final_review` (`run_in_background: false`) with the package, the plan and that list, to triage which minors block. Re-grade findings by effect. One fix subagent gets the complete findings list, real gaps included (`kern:implementer`, a step 6 brief), each fix red then green; then one `re-review` on `model.final_review` of its diff from `final.diff`'s second line, packaged with an `--allow-file` per task, dispatched as the whole-branch review is. Residual findings go to the user in step 13.
13. Finish: report decisions with the cost if wrong, parked items, deferred minors and their triage, verification commands with output, worktree and branch. `ledger-open --summary` must end with `main: unchanged`; anything else goes first in the report. No push or PR, no commit beyond step 10's; offer `/kern:commit` and `/kern:finish-branch`. Under autopilot, end the report with a catch-up per `${CLAUDE_PLUGIN_ROOT}/skills/recall/references/chat.md`.
14. Propose teardown, do not run it: each fork with the `git worktree remove` command `${CLAUDE_PLUGIN_ROOT}/skills/parallel-work/references/worktrees.md` allows, the plan worktree once committed; run them only on yes.

## Inputs

| Key | Default | Use |
|---|---|---|
| `base_branch`, `branch.pattern`, `worktree.dir`, `worktree.setup` | detected; `kern/{slug}`; `.claude/worktrees` under MAIN; none | worktrees |
| `test.focused`, `test.full`, `typecheck` | detected, source printed | checks |
| `shared_services`, `parallel.max`, `scope_threshold`, `review.rules`, `generated_artifacts` | none; 3; 4; project prose; none | waves, review |
| `model.implementer`, `model.reviewer`, `model.final_review` | `sonnet`, `opus`, `opus` | models |

## Outputs

`WORK/ledgers/<plan-slug>/`, the plan worktree's changes and a chat summary.

## Stops and autopilot

Ask at each stop as a typed reply in chat, never through AskUserQuestion. Autopilot is on per the latest kern signal (an `autopilot ON:` reminder or a `kern mode:` line with `autopilot=on`), else the kernel's "Autopilot:" line; a turn with no mode line changes nothing. When on, steps 1 and 2 and a failed `wt-new` still end the run. A later stop parks as `parked: <question>; default: <choice>; why: <one line>` in the ledger: a question takes its default (the plan's text; a red baseline goes on, naming red-before tests), a stopped task stays open with every task blocked by it, and disjoint tasks continue. One commit per closed task when its checks pass, through `/kern:commit`; G5 allows only `git commit -m` or `-F <file>` on an unprotected branch. Without autopilot `commits: ask` holds: no commit. Push and a draft PR only through finish-branch; teardown never runs. Isolation, serialization, expand and contract, read-only production, the round cap, tests and secrets do not loosen.

## Red flags

| Thought | Reality |
|---|---|
| "Close enough on spec compliance" | Spec issues mean not done. Fix them or reach round 3 and escalate. |
| "I'll fix it myself; dispatching is overhead" | A fix outside the loop skips review. Resume the implementer, then re-review. |
| "One more round will converge" | Past round 3 the failure is structural. Stop with a split proposal. |
| "The fix was small, skip the re-review" | task-done refuses a tree no review approved. Re-review every fix. |
| "This finding is wrong, I'll drop it" | Argue it in the re-review. At the cap, the split proposal names it. |
| "Ledger bookkeeping is overhead" | The ledger is what survives compaction. Write each line as it happens. |
