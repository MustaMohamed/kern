# self-review: acceptance checks (run during the M2b pilot)

- [ ] The diff adds `it.skip(`: the floor scan flags it; the verdict is not `ready`.
- [ ] The diff changes a shared function with five external callers: the writer sweep lists them with paths, and one fact is run.
- [ ] A spec exists: the Spec lane quotes its acceptance lines and its findings stay apart from the Standards findings.
- [ ] A project with `.claude/skills/self-review/`: kern defers in one line.
- [ ] The built-in `code-review` is missing: a skip line appears; the other steps run.
- [ ] The built-in lane receives the worktree path as its target and reviews that worktree's diff (record what it reviewed; if a path target is not accepted, note it for M3).
- [ ] `origin` exists but the fetch fails: the skill asks (under autopilot it parks and goes on with the last fetched ref), the report says "base not refreshed", and a clean diff gets `rebase first`.
- [ ] The repo has no `origin` remote: the base ref is the local base branch, said once, and the rebase check runs against it.
- [ ] `origin/<base>` moved on a file the package changed since the merge base: the verdict is `rebase first`, and the skill rebases nothing.
- [ ] The tree equals the merge base: wt-diff exits 3 and the skill says there is nothing to review.
- [ ] A new guard test whose probe exits 3 for any reason but a new module or a test-only patch: the report says inconclusive and the verdict is `fix first`.
- [ ] The branch changes only test files: the probe exits 3 as inconclusive, and that alone does not fail the check or make the verdict `fix first`.
- [ ] The branch adds `src/two.js` and `test/two.test.js`: the probe exits 3 on the missing module, the report says `probe inconclusive: new module`, a `--mutate` probe on the new code's condition runs, and that probe alone does not make the verdict `fix first`.
- [ ] A second run on the same branch writes `<slug>-2.diff` and a since package; a `blocker` or `should-fix` finding on a line the previous round's findings asked to change, or a package newly over `scope_threshold` paths, gives `split`; the first run never does.
- [ ] Round 1 says `fix first` and the user fixes the findings: in round 2, a `nit` on a line the round 1 findings asked to change does not give `split`. Round 1 says `ready`, more work follows within `scope_threshold` paths, and finish-branch runs round 2: a `should-fix` finding in the new work gives `fix first`, not `split`.
- [ ] The diff moves a test into a `describe` block with the same assertions and renames a variable: no finding names either; each behaviour-keeping change lands in Cleared with its check. A function the diff adds with no test gets no finding of its own: the missing test is one line under the finding it would have caught; with no such finding, the missing test is one line under `Untested`, not a finding, and the verdict ignores it. No nit is a guess called probably fine, style advice or a first-round split idea.
- [ ] A repo with a lint script and no typecheck: `verify.fast` runs lint alone, with no ask and no failed check, under autopilot too.
- [ ] The diff adds a function with no test and nothing else to report: the report lists the missing test under `Untested`, in no findings class, and the verdict is `ready`.
- [ ] The diff breaks a caller in a file it does not touch: that is a finding at the caller's `path:line`. A defect the diff did not cause is filed as `pre-existing`. A smell from the baseline is reported as a `nit`.
- [ ] The diff's only finding is a smell from the baseline, such as possible Feature Envy: it is filed as a `nit`. A smell alone leaves the verdict `ready`.
- [ ] The prompt says "Do not edit files": steps 1 to 3 still run, the built-in lane included; the package goes under `kern-dir reviews`, and no file the user owns changes.
- [ ] The diff swaps inline rounding for an equivalent helper: the helper is under Cleared with its check, never a finding or `pre-existing`.
- [ ] The diff adds an export with no caller yet and nothing wrong in it: no finding names it.
- [ ] The diff lowers a coverage threshold and the author justifies it: the `bar-lowered` hit is not under Cleared, and the verdict is `fix first` until the user types yes for it in chat or a revert is committed with the work's files. A yes typed earlier in the session stands; with it, the hit is under Cleared and the PR body's Merge danger names the change. Under autopilot, with no yes, the revert is committed with the work's files, a `parked:` line says so, and the pushed head holds the revert. A justified `debug-print` hit still goes under Cleared.
- [ ] The diff bumps one dependency in `package.json` and its lockfile, and no changed symbol has callers outside its directory: step 6 opens `references/blast-radius.md`; the report names the changelog it read, the lockfile diff it read and the suite runs before and after. Thin tests around what the dependency does are a finding, not `Untested`.
