## [Unreleased]

- Session state: a read of the state file that fails no longer resets it. prompt-submit, on every prompt and command expansion, and session-start, on `compact` and `resume`, reset the state whenever `state_get` failed, file present or not; `state_reset` then wrote the default voice and surface, `autopilot: off` and a new `since`. The 2026-10-21 exec hook traces show it twice: a UserPromptSubmit (`/kern:commit`, commit-work-file) and a UserPromptExpansion (`/kern:finish-branch`, finish-pr-at-head) each rewrote a state that read `autopilot: on` in `state_reset`'s key order, so autopilot turned off mid-session and the guards asked, which a headless run refuses; replayed offline, the same input kept it on. Both call the new `state_ensure`, which writes the default state only when the session has no state file. When a read of an existing file fails, it is tried once more; when that fails too, the file is left as it is and that call's readers fail safe: autopilot reads off, so a guard asks. The read's error now reaches the hook's stderr, which the exec trace keeps. `state_set` writes nothing when its read of the existing file fails twice, where it wrote a state holding only the new keys, autopilot lost; a failed rename exits 2 and leaves no temp file. Neither `state_ensure` nor `state_set` takes the state path or reads the state through a command substitution, since one whose pipe cannot be made (a full fd table) gives status 0 and no output, which read as no file or an empty state: awk copies the old lines straight into the new file. Startup and `/clear` still reset.
- Exec evals trace kern's hooks. The plugin copy's hooks.json runs each kern hook through `hooks/trace` (from `evals/exec/hooks/trace`), which gives the hook its stdin, argv and environment unchanged, except that under bash 5 SHLVL is one higher (kern reads no SHLVL), and keeps its stdout, stderr and exit code. While `KERN_EXEC_TRACE` names a file, which each case sets beside its workspace, the trace appends one JSON line per call: the time, pid, ppid and directory, the hook input, `CLAUDE_PLUGIN_DATA`, `CLAUDE_PLUGIN_ROOT`, `CLAUDE_PROJECT_DIR`, `CLAUDE_CODE_SESSION_ID`, `CLAUDE_CONFIG_DIR`, `HOME`, `TMPDIR` and `PATH`, kern's own view from its libraries (the session id, cwd and main worktree it resolves, the state file with its mtime, inode and `autopilot:` value, and its text unless it or its folder is a symlink, which kern refuses too, each settings layer's `autopilot:` value, and whether autopilot reads on), and the hook's output and exit code. Every line is strict UTF-8 JSON: a byte sequence that is not UTF-8 reads as U+FFFD, or is dropped where there is no perl, while the hook's own output keeps its bytes. Each case's trace is saved as `<id>.trace.jsonl` beside its events, a cut-off or invalid case's too. A trace killed at the hook's timeout leaves its work dir, and maybe its lock; the next call sweeps the one and breaks the other when its holder has ended or it is older than 5 seconds, so no later call waits on it. On 2026-10-21 G5 asked in two autopilot runs whose state read `autopilot: on` (Task 16l); the trace tells a hook input that names another session, or none, from a user layer that denies autopilot. kern's hooks and the repo's hooks.json are unchanged, and no run is graded differently.

A quoted here-doc delimiter (`<<'EOF'`, `<<"EOF"`, `<<\EOF`) keeps its body as data. A string a builtin evaluates as arithmetic or a subscript (`let`, `declare -i`, `typeset -i`, `local -i`, `printf -v`, `read`, `[[ ... -eq ... ]]`) with a `$( )` or backtick in single quotes is denied under autopilot, as is any command holding an array subscript that opens with a substitution after a name, written in single quotes or in a quoted here-doc body (`'a[$(cmd)]'` stored and later evaluated, as in `x='a[$(cmd)]'; echo $((x))` or `x=$(cat <<'H'` / `a[$(cmd)]` / `H` / `); echo $((x))`); a regex class such as `grep '[$(]'` is not one. A subscript built at run time, as by `x+=`, is not read (an M3 limit). The body itself is data: a body that starts with `$(date)` is not denied as a command name built at run time. If one of `git_words`' awk programs ever fails, it emits the `$KERN_UNREAD` record that G00 denies and keeps the records it has, rather than reading less than the shell runs.
- Guards find where each `$( )`, backtick, quote, `$(( ))`, `$[ ]` and `${ }` ends as bash and zsh do: each `$( )` and backtick holds quotes of its own. A quoted paren or quote inside a `$( )`, an ANSI-C quote such as `$'it\'s'`, a comment inside `$( )` and an escaped backtick inside a backtick no longer hide the commands after them, as in `echo $(echo '(' $(git push --force origin main))` and `echo "$(echo '"')"; git push --force origin main`, which 0.3.0 missed. `$'...'` inside `$(( ))` and a newline inside `$[ ]` are read too. A `case` inside a `$( )` is read, so a command in a `case` clause there, such as `echo "$(case x in x) git push --force origin main ;; esac)"`, still reaches a guard. Where bash and zsh read a shape differently, or a quote never closes, the guards read it both ways; a command nested past the reader's depth limit is denied under autopilot.
- A headless session (`claude -p`, the Agent SDK) starts in the normal voice even when `mode.voice` is `terse`; `mode.voice.headless: terse` opts back in, and `/kern:mode terse` still switches. The kernel, the per-prompt reminder and subagents agree. Terse keeps the reply language fixed: an explicit language instruction wins, and quoted text, logs and errors never switch it; one term per thing, and a pronoun only with an obvious referent.
