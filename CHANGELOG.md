## [Unreleased]

- Guards read through zsh's precommand modifiers `noglob` and `nocorrect`, and through `coproc` and `repeat` with its count, to the command after them. `noglob eval 'git push --force origin main'`, `nocorrect eval`, `repeat 1 eval`, `coproc eval`, `repeat -1+2 git push --force origin main` and `noglob sh <<EOF` with a push in its body are denied in both modes, where under autopilot they got no vote. A command behind one gets the vote it gets alone, so `noglob cat <state file>` is a read, as `cat` is. G1, G5 and G6 count a `cd` behind `noglob`, `nocorrect` or `repeat N` as a move, and judge where git would run both with and without it; one under `coproc`, `repeat 0`, or a reserved word zsh does not find as one (quoted, or after `noglob` or `nocorrect`) is not a move for them. A modifier word after the command name, such as `cd x 2> noglob`, changes nothing.
- Guards G16 and G20 follow a `cd`, `pushd` or `popd` only when it is the command name of its simple command, with only unquoted assignments and redirections before it (zsh runs a quoted `'X=1'` or `'2>/dev/null'` as a command). An upper-case `CD`, which on macOS runs `/usr/bin/cd`, is not plain either: G16 reads every `cd` in a command that holds one as a maybe. A `cd` behind a zsh modifier or reserved word (`noglob`, `nocorrect`, `coproc`, `repeat`, `time`, `!`, `if`) or a wrapper (`command`, `builtin`, `exec`, `nice`, `nohup`, `env`, `timeout`, `sudo`) may run in a subshell, run `/usr/bin/cd`, which never moves the shell, or not run at all. On such a `cd` G16 keeps its readings and adds the target's, and G20 judges from both directories, up to 16 of them; past that it denies a relative or Markdown write, and judges a read as before. G20 reads each simple command once, and judges it once when nothing in it depends on the directory. A Markdown write in a command that names more than 1024 files is denied, since G20 would not read them all. So `cd <sessions> && nice cd /tmp; echo x > foo` and `noglob time cd /tmp; cp approved.md x.md` are denied, where they got no vote. G20 takes `builtin cd`, and a `cd` that can go back (`cd -`, `cd ~-`, `cd +1`, a target built at run time such as `"$OLDPWD"`, `popd`), as a maybe too, and adds HOME and every directory the command was in.
- Guard G1 judges a push after a `cd`, or under `env -C` or `sudo -D`, where it would run without the move too, so that judgement's deny holds: `cd . && git push --force-with-lease origin feat` over another author's commit is denied, where it asked. The ask that the directory is unknown stays, and is still denied under autopilot.
- Guard G16 keeps its reading of a `cd` into a `.claude` directory or the sessions dir across a later `cd` whose target it cannot know: no operand, `-`, `+N`, two operands, `~user`, a `$`, a backtick or a glob, or a relative path after one of these. So `cd ~/.claude && cd "$(git rev-parse --show-toplevel || echo .)" && sed -i '' s/a/b/ settings.json` asks, and is denied under autopilot, where before it got no vote; a write after such a `cd` from the sessions dir stays denied. Such a `cd`, and `popd`, can go back to a directory the command was in, so it also takes back every reading held earlier in the command: `cd <sessions> && cd /tmp && cd - && echo x > foo` is denied, and `cd ~/.claude && cd /tmp && cd ~- && sed -i '' s/a/b/ settings.json` asks. A `cd .`, or any relative `cd` from the sessions dir, keeps the reading too. A `cd` to an absolute path, `~` or `~/path` still ends it. G16 follows a `cd` to a known target as text, so a relative `cd` that leaves a `.claude` directory ends that reading, and one that comes back into it, as in `cd ~/.claude && cd agents && cd .. && sed -i '' s/a/b/ settings.json`, restores it. Known limits: a `cd` to a known target that fails, followed by `;`, is still taken as a move (`cd ~/.claude && cd /nonexistent; sed -i '' s/a/b/ settings.json` gets no vote); so are bash's `pushd -n`, which does not move, and a `cd` that runs in a subshell, a pipeline or the background (`( cd /tmp )`, `cd /tmp | cat`); a relative `cd` that CDPATH (or zsh's cdpath) resolves elsewhere is followed as if from the current directory; and a path through a symlink into the sessions dir is not read as the sessions dir, since G16 matches state by path text.
- Guard G6 still scans the current repository for a commit or push after a `cd`, or under `env -C`, `--git-dir`, `--work-tree`, `GIT_DIR=` or `GIT_INDEX_FILE=`, so a secret staged there is denied in both modes; before, `(cd .); git commit -m x` with a staged key only asked. The ask that it could not scan the moved part stays, and is still denied under autopilot.
- Guards judge a Bash command whose head word is a shell alias from the Claude Code shell snapshot, such as `gpf! origin main`, as the git or gh command it expands to, as well as itself. With aliases loaded, the guards read the command's own simple commands exactly as without aliases, in the same order and context, then every expansion after all of them, so an alias can only add votes: it never removes a deny or an ask, and never gets an allow, which kern gives only to a command that starts with git or gh. The head word is found after assignments (quoted ones included), redirections and zsh's reserved words (`if`, `!`, `time` and the like), in each simple command, `$( )` and `eval`. An alias whose value ends in a space, such as `_='sudo '`, also expands the word after it, as zsh's trailing-space rule does, so `_ gpf! origin main` is judged as `sudo git push --force origin main`; past 8 such words, a word that is still an alias is denied under autopilot. G2, G3, G4, G13, G14 and G15, which skip a command whose text names no gh, push, deploy tool or network client, read the expansion's text too, so `prc` for `gh pr create`, `gp origin production` as a push to a deploy branch, and an alias that runs psql against a protected target are judged. kern reads the snapshot as text and never runs it; a missing, unreadable or unparseable snapshot changes nothing. It caches the parsed table in its state dir, keyed by the snapshot's path, size, modification and change times and inode, and reads the cache as data the same way; a forged cache, like a forged snapshot, can only add votes. Shell functions in the snapshot are read too: a function whose body names git or gh, such as oh-my-zsh's `ggf` (a force push), `ggfl`, `grename` (a remote branch delete) and `gbda`, is judged as an unknown git or gh command, so `ggf feat` and `grename feat x` ask, and are denied under autopilot, since kern cannot see what the function runs; an alias whose head word is such a function is judged the same way, and a function with no git or gh word changes nothing. This removes the 0.2.0 known limit on shell aliases. Known limits, left for M3: a function that runs git only through another function or an alias (oh-my-zsh's `ggpnp`) is not judged, nor is a function in any shape but zsh's `name () {` and bash's `declare -f` output; the newest snapshot stands in for the session's, which the hook input does not name; an alias defined and used in one Bash call through `eval`, `$( )` or a backtick is not judged interactively (G00 denies the definition under autopilot); nor is an alias past another alias's head word, a global alias, a `$'...'` or double-quoted alias value, a chain of aliases deeper than 8, or interactively an alias past 8 trailing-space words; an expansion no longer sets context for the command's later records, so `gaa && git commit -m x` loses G6's stale-index reason (its decision stays); a snapshot with thousands of aliases slows every Bash call, by about 0.6 s for 10,000; G16 and G20 match only the command's own text, not an alias's expansion; and the shell-snapshots folder is writable, so kern reads a newer snapshot written there, though that can only add votes, never remove a deny or an ask or add an allow.
- help: allows only the exact git commands it prescribes (`git remote -v`, `git rev-parse --git-common-dir`, `git check-ignore -q *`, `git worktree list`); `git remote *`, `git symbolic-ref *` and `git log *` could write config, move HEAD or run a program with no prompt.
- Mode switches: "terse voice" and "terse mode on" switch; extra spaces are folded; a first line over 200 characters never switches.
- Kernel: no is an acceptable answer, and chat in either voice skips the main AI tells; terse keeps existing comments and shows only changed code.
- prove-it: evidence before any done, fixed or passing claim; a probe made inconclusive by a module or export the change adds, or a test-only patch, is reported as `probe inconclusive: new module` and the new code is proven with `probe --mutate`. Removes the M0 placeholder skill.
- Agents implementer, task-reviewer and investigator.
- floor-scan: the G7 check as a script, with a lowered-bar class and ratchet.<metric> settings keys.
- Guard G18: kern's read-only investigator may run only allowlisted read commands.
- Guard G16 asks, and under autopilot denies, a Write, Edit or NotebookEdit whose target resolves under kern's own hooks/ directory (as written, through `..`, through a symlinked directory or through a symlink to the file), and any Bash command whose text names a hook entry file (prompt-submit, session-start, subagent-start, pre-tool-use), a .sh file under hooks/lib/ or hooks/guards/, or a state function, reads included; hook files stay readable through the Read and Grep tools. Running prompt-submit with a made-up prompt could forge the user's message or turn autopilot on, and an edited guard could stop voting. Skill, doc and test files under kern's root get no vote. Known limits: a shell write that reaches a hook file without naming its path (a path in a variable, find -exec, a script run by name) is not seen, and hooks/hooks.json is covered for Write and Edit only.
- Guard G20: a Markdown spec or plan becomes approved, or changes its approved: line, only with a quote of one whole line of the user's last message, judged on the file as the edit leaves it; never under autopilot. The quoted line must hold a yes word (yes, y, yep, yeah, ok, okay, sure, go, go ahead, approve, approved, lgtm, ship it, do it, proceed, confirmed, agreed), no negation or hold word (no, nope, nah, not, don't, dont, never, wait, stop, hold, later, cancel) and no final question mark, so "No, not yet.", "Don't approve it yet", "Can you change the title?" and "sounds good" do not approve. A frontmatter with more than one approved: line, in any case or indentation, is denied, so G20 and ledger-open read the same quote.
- implement: thin slices, failing test first, mutation and fail-then-pass probes, full suite.
- diagnose: red-capable loop before hypotheses, a debugger or REPL before logs where there is one, fix with a regression test proven by probe, and the confirmed hypothesis carried into the commit or PR body's why; loop-rate for flaky bugs, and find-polluter, which runs the test command with no stdin so a runner that reads stdin cannot eat the file list.
- define: clarify, classify and get an explicit, quoted approval before code; specs carry a Constraints section.
- plan: approved spec to ordered tasks with exact files and verify commands, checked by plan-check, then reviewed by a general-purpose subagent on `model.reviewer`.
- parallel-work: fan out with one worktree per writer, checked briefs and serial integration; the brief lets a worker write its report file outside its worktree.
- execute-plan: ledger, per-task worktree snapshots and two-verdict review without commits; approval, review and RED checked by scripts. On resume, a round whose report says DONE or DONE_WITH_CONCERNS goes to review and any other status to the status step; a `Decision:` line records a ruling, the user's or a mechanical one.
- self-review: deterministic checks, built-in code-review at low effort, a spec lane, blast radius, probes, verdict. A guard test's probe that exits 3 because the branch adds the module or export it loads, or because the patch holds only test files, is reported as `probe inconclusive: new module` and does not fail the check; a `probe --mutate` on the new code is the proof, so a branch that adds a module with its test can reach a draft PR.
- commit: named files, convention-checked message from a file under .kern/tmp, one commit per reviewed task run as `git -C <worktree> commit`, no attribution by default. commit and finish-branch read the branch with `git symbolic-ref -q --short HEAD`, whose exit 1 means a detached HEAD.
- finish-branch: verify, self-review and size gate before the commit, push or draft PR menu; the PR has a title, a body under .kern/tmp and a dedup on the head commit. prove-it hands commits and PRs to these skills.
- recall: rebuild state from kern working files, this project's transcripts and live state; replaces the user-level recall skill.
- Kernel: M2's routes live in kernel/routes.md, which the Routing rule points to, for define, plan, execute-plan, implement, diagnose, prove-it, self-review and recall; routing evals with fixed floors and a frozen held-out set; lint rule 12 and a standing-cost budget.
- Session state keys, kern-dir names and worktree slugs are checked in the C locale, and G13 reads `nc` as a word the same way: in en_US.UTF-8, bash 3.2 matched `[a-z]` against upper-case letters and letters such as `é`, so `state_set` took the key `Voice`, `kern-dir Tmp` and a `café` slug passed, and G13 skipped `énc` (the first GitHub CI run on macOS failed on the state key).
- Hooks run git with no fsmonitor program and no repo hooks (git 2.31 or later). With an older git, or one whose version cannot be read, session-start says so in one line.

## [0.2.1] - 2026-10-14

- PreToolUse asks, or denies under `bypassPermissions`, when a hook library cannot load or lacks a function it defines. In 0.2.0 a missing `settings.sh` or `decide.sh` gave no decision at all. session-start says when kern did not load.
- pre-tool-use and session-start leave POSIX mode first, so `POSIXLY_CORRECT` cannot skip that check.
- A natural-language voice switch fires only when the phrase stands alone on the first line, such as `go terse`, `turn off terse mode` or `back to normal`, with a leading `please` or `ok` and a trailing `please`, `now`, `.` or `!` allowed. More phrases switch, and prompts such as `use terse variable names` no longer do. A 200-case corpus tests the hook.
- No mode line or terse reminder on scheduled-task prompts.
- session-start removes session state files untouched for 30 days.

## [0.2.0] - 2026-10-13

- Kernel and subagent kernel, rendered at session start and subagent start, with the project settings summary.
- Mode switching (`/kern:mode`, natural phrases) and the per-session autopilot grant (`/kern:autopilot`), which only a typed command turns on.
- Settings layer (`.claude/kern.local.yml`, `.claude/kern.yml`, `~/.claude/kern.yml`) and `scripts/kern-root`, `kern-get`, `kern-dir`, `kern-detect`. Safety lists (`protected_targets`, `never_commit`, `branch.protected`, `deploy.envs`) are the union of every layer.
- Guards G1 to G6 and G13 to G16 through one PreToolUse dispatcher. A guard allows only a proven command shape and asks for anything else; under autopilot every ask is a deny.
- Git write commands and gh commands behind a wrapper (`env`, `sudo`, `xargs`, `caffeinate`), git aliases and git extensions ask, because kern cannot see what they run.
- G13 treats `protected_targets` as read-only: it lets through only proven reads (ssh read commands, plain SELECT and similar, copies from the target) and denies everything else in both modes. A remote `cmd` or PowerShell wrapper denies, and so does SQL that needs more than plain lexing (comments, backslashes, dollar-quotes, E-strings, doubled quotes). Entries may be a host, a host:port such as an SSH tunnel, or an sqlite path.
- G14 allows tracker writes under `tracker.policy: auto` only for a closed list of Linear and Notion tools and proven `gh issue` and `gh label` shapes. GitHub MCP writes and every delete always ask.
- G15 asks before deploys and publishes, from a table of 76 command names, named anywhere in a command.
- Under autopilot, G00 denies commands kern cannot read: command names built at run time, shell scripts it cannot parse, and code piped into a shell. Interpreter code in files and here-docs still runs.
- gh aliases and extensions ask, and so does any write to Claude Code's own settings files (`.claude/settings.json`, `.claude/settings.local.json`, `~/.claude/settings.json`).
- A committed `.claude/kern.yml`, or a `kern.local.yml` that git tracks, cannot turn kern off or loosen a policy; a committed `base_branch` cannot unprotect the default branch.
- Skills `mode`, `autopilot`, `help`, `unslop`, `technical-writing`; the terse voice.
- Lint rules 6, 7, 13 and 15; hook tests on bash 3.2 and 5; CI runs the hook suite.
- Known limits: shell aliases from the Claude Code shell snapshot (such as `gpf!`), `GIT_CONFIG*` environment settings, ANSI-C quoting, package scripts, interpreters and variables can hide a command from the guards. A command over about 40 KB times out in the hook and is blocked.
